# AutoXP3の最適化エンジンを解剖する ― 10サンプル検証から見えるアルゴリズムの実力と限界

> 本記事は、AutoXP3の出力サンプル（`Sample1.xlsx` 〜 `Sample10.xlsx`）に対して独自にRコード（Pythonによる再実装）を走らせ、アプリの推薦候補とNoteシートの正解条件を突き合わせた検証レポート（`R_code_vs_Note_comparison.xlsx`）をもとに整理したものです。
> AutoXP3の公式仕様書ではなく、実行結果のリバースエンジニアリング的な解析である点をあらかじめお断りしておきます。

---

## 1. AutoXP3のモデルアーキテクチャ（検証から推定）

AutoXP3が内部で動かしているモデルは、サンプル検証の結果から次のように推定されます。

```
y = Xβ + u + ε
β  ~ N(0, 100·I)              （線形係数の事前分布、原スケール）
u  ~ GP(0, K_RBF(ℓ=0.4) + K_cat(σ²=0.5))   （ガウス過程による非線形残差）
ε  ~ N(0, σ²=0.05)            （観測ノイズ）
```

一言で表すと **「線形回帰 + ガウス過程（GP）のセミパラメトリックBayes」** です。線形項が全体のトレンドを捉え、GPが線形では表現できない非線形構造・局所的な変動を吸収する、という役割分担になっています。カテゴリ変数には `K_cat`（カテゴリカルカーネル）が使われており、連続変数とカテゴリ変数を単一のモデルで統一的に扱えます。

最適化候補の提示には **UCB（上側信頼区間）スコア** が使われています。スコアは各候補点の予測平均 + κ × 予測標準偏差として計算され、κの値によって「活用（Optimize）」と「探索（Explore）」の2モードが切り替わります。

---

## 2. OptimizeモードとExploreモードの設計思想

AutoXP3が提示する候補には、以下の2つのモードが存在します。

| モード     | κの値 | 狙い                               | 典型的な挙動                             |
| ---------- | ----- | ---------------------------------- | ---------------------------------------- |
| `Optimize` | 0     | 現時点で最も良さそうな条件を推薦   | 予測値が高い領域に集中する               |
| `Explore`  | 2     | モデルが不確かな領域を優先的に提案 | 訓練データから遠い、SDが大きい点を選ぶ |

`Optimize` では κ=0 なので UCBスコア = 予測平均そのものです。モデルの学習精度が高ければ、真の最適条件に近い候補が上位に並びます。一方 `Explore` では κ=2 の加算項が効くため、**「予測は良くないが不確実性が高い」** 条件が積極的に推薦されます。実験コストが低い段階では Explore で空間をカバーし、有望な領域が絞れてきたら Optimize に切り替える、という使い方が意図されていると考えられます。

各モードのTop候補数は「TargetY別に上位3件 + All（全Y出力の幾何平均デザイラビリティで上位5件）」で構成されており、多目的最適化の場合はYごとに最適条件が異なるトレードオフを可視化できる設計になっています。

10サンプルすべてに対して、Optimizeモードの第1位候補をNoteシートの正解条件と突き合わせた結果は次のとおりです。

| 判定         | 件数 |
| ------------ | ---- |
| ✓ 一致       | 7    |
| ~ 部分一致   | 3    |
| ✗ 不一致     | 0    |
| 合計         | 10   |

完全不一致が1件もなかった点は、モデルの汎化性能の高さを示しています。また、10サンプルすべてで R² ≥ 0.996 という高いフィット精度が得られており、サロゲートモデルとしての回帰性能は一貫して安定していました。

## 4. 各サンプルの詳細検証

### 4-1. 完全一致した7例（✓ Match）

7例に共通するのは、**目的関数の主効果が明確で、交互作用項があっても方向性が一意に定まる** ケースです。

**Sample1（1変数線形）**は最も基本的なケースです。真のモデル `Y1 = 2.0*X1 + 1.0` に対して、フィットした線形係数は `β(X1) = 1.9803`（切片 -0.066）となり、R² = 1.0000、RMSE = 0.034 という精度でした。Optimizeの第1位候補は `X1 = 10`、予測Y1 = 20.74（±3.50）で、正解条件「X1 = 10を最大化」と完全一致しています。

**Sample2（2変数線形）** は `Y1 = 1.5*X1 + 2.0*X2 + 0.5` という2次元線形問題で、R² = 1.0000、RMSE = 0.024。フィット係数は `β(X1) = 1.459、β(X2) = 1.989` となり、正解 `X1=10, X2=10` を正確に指し示しました。

**Sample5（指数関数 + カテゴリ）** は `Y1 = 4.0·exp(-X1) + 0.8·X2 + カテゴリ効果` で Purpose が `<10`（最小化）という問題です。R² = 0.998、RMSE = 0.136 とほぼ完璧なフィットで、Optimizeは `X1=10, X2=0, X3=A`（予測 Y1 = -0.57）を提案。正解「X1大・X2小・カテゴリA」と完全一致しました。

**Sample7（多目的：Y1 vs Y2のトレードオフ）** は、2出力が `Y1 = 2.0*X1 - 1.2*X2 + ...`、`Y2 = -2.0*X1 + 1.2*X2 + ... + 20` という互いに相反する構造を持ちます。Y1向けの最良候補は `X1=10, X2=0`（予測22.1）、Y2向けは `X1=0, X2=10`（予測33.5）と、トレードオフを正確に捉えた推薦結果になりました。R² はY1 = 1.0000、Y2 = 0.9999 で、係数推定の精度も真値（Y1の X1係数=2.0 vs 推定1.985、X2係数=-1.2 vs 推定-1.189）に非常に近いものでした。

**Sample9（交互作用 + カテゴリ）** は `Y1 = 0.8*X1 - 1.1*(X2*X3) + カテゴリ効果（A=0, B=2, C=4）` という問題で、Optimizeは `X1=10, X2=0, X3=0, X4=C`（予測33.2）を提案。正解「X2・X3を小さく、カテゴリC」と完全一致しました。

**Sample10（6変数 + 指数項）** については後節で詳しく触れます。

### 4-2. 部分一致した3例（~ Partial）とその理由

部分一致になった3例（Sample4, Sample6, Sample8）は、いずれも **交互作用項の存在がモデルの線形成分を「誤った方向」に引っ張ってしまう** という共通構造を持っていました。

**Sample4（周期関数、ターゲット最適化）**

真のモデルは `Y1 = 3.0*sin(X1) + 0.8*X2 + 0.5*X3` で、Purpose は `=5`（ターゲット最適化）です。フィット結果（R²=0.997）は良好でしたが、アプリが内部的に purpose を `'None'` として扱っていたことが検証レポートから判明しました。

Optimizeが提案した第1位は `X1=2, X2=5, X3=9`（予測10.93）で、目標値5に対してオーバーシュートしています。ただし X1=2 という選択は sin 関数のピーク（π/2 ≈ 1.57）近傍を捉えており、X1に対する周期依存性は正しく学習されていると言えます。部分一致となった主因は `=5` という目標値制約の取り扱いが完全ではなかった点にあります。

```
真値:  Y1 = 3.0*sin(X1) + 0.8*X2 + 0.5*X3
提案:  X1=2, X2=5, X3=9  →  Pred.Y1 = 10.93 (±7.16)   ※目標は5
正解:  X1をπ/2付近に制御する周期問題
```

**Sample6（4変数 + 導出変数 X1*X2）**

真のモデルは `Y1 = 1.2*X1 + 1.0*X2 - 0.8*(X1*X2) + 0.7*X3 + 0.5*X4` で、DataシートにはX1とX2の積 `X1*X2` が導出変数として列に加えられています。R²=0.9998 と非常に高精度ですが、モデルが推定した線形係数は `β(X1) = -1.971、β(X2) = -2.553` と **両方が負** になりました。

これは `X1*X2` 項の交互作用ペナルティ（-0.8）がGPではなく線形成分に吸収されたためと推測されます。その結果、Optimizeは `X1=0, X2=0, X3=9, X4=7` という「X1・X2をゼロに設定してペナルティを回避する」戦略を選びました。正解は「X1とX2をバランスよく高く取ってX3・X4も高くする」なので、X3・X4の方向は合っていますがX1・X2の扱いが違います。

```
フィット係数:  β(X1)=-1.971,  β(X2)=-2.553  ← 交互作用が線形成分に「流出」
真の効果:     X1が高いほど良い（X2が低ければ）
提案:  X1=0, X2=0, X3=9, X4=7   ~ Partial
正解:  X1=10, X2=0, X3=10, X4=10
```

**Sample8（5変数 + 強い交互作用 X1*X2）**

Sample8は、Sample6と類似した問題構造（`X1*X2` 交互作用）に加えて、係数がより強い（-1.0 倍）ため、線形成分への流出も顕著でした。更新データ（全5変数が可変）でフィットしたモデルの線形係数は `β(X1) = -2.445`、`β(X2) = -3.458` と大きく負になり、Optimizeが `X1=0, X2=0` を推薦し続けています。

一方で X3・X4・X5の方向（高いほど良い）は正しく捉えており、真の最大値 `Y1=25.00`（X1=10, X2=0の場合）に対して、提案条件での真値は 15.00 まで改善しています（旧データでは 5.80 だったため大幅に向上）。X1=10・X2=0 近傍にさらなる実験データを追加することで、次のサイクルで完全一致に近づく可能性が高いです。

## 5. データ品質が鍵を握った2例（Sample8・Sample10）

### 5-1. Sample8：交絡データから脱する

旧データ（Sample8の元バージョン）では X3=3、X4=4、X5=5 が固定値に近く、これらの変数の効果が適切に学習されていませんでした。全変数を可変にした新データでフィットし直したところ、R² が大幅に向上し（R²=0.9997、RMSE=0.024）、X3・X4・X5 の正の効果が正確に推定されました。

| 指標               | 旧データ | 新データ |
| ------------------ | -------- | -------- |
| R²                 | 低       | 0.9997   |
| RMSE               | 大       | 0.024    |
| 提案条件での真Y1   | 5.80     | 15.00    |

この事例は「**変数が固定されていると、その変数の効果はモデルが学習できない**」という機械学習の基本原則を実データで示しています。AutoXP3 に限らず、サロゲートモデル全般に共通する教訓です。

### 5-2. Sample10：交絡を断ち切って正解に到達

Sample10の真のモデルは `Y1 = 0.7*X1 + 0.5*X2 + 0.6*X3 + 0.4*X4 + 2.5*exp(-X5) + 0.4*X6` で、X5が指数関数的に作用するという非線形性を持ちます。旧データでは X5 が X1・X2 と交絡しており、X5の係数が正方向に誤推定されていました（→ Optimizeが X5=10 を誤って推薦）。

X5 を X1・X2 から独立に変化させた新データで再学習した結果、推定係数は `β(X5) = -0.159`（負：正解）となり、Optimizeの第1位推薦が `X1=X2=X3=X4=X6=10, X5=0` に変わりました。これは正解条件「X5を低く、他を高く」と完全一致しており、検証スコアも `✓ Match` に昇格しています。

```
旧推定:  β(X5) > 0  → X5=10 を推薦（誤り）
新推定:  β(X5) = -0.159  → X5=0 を推薦（正解）
予測SD:  ±17.67（旧）  →  ±7.30（新）  ← 不確実性も大幅に低下
```

## 6. フィッティング精度の全体像

10サンプルの R² と RMSE をまとめると、セミパラメトリックBayesの安定した汎化性能が確認できます。

| サンプル  | 目的(Purpose) | R²     | RMSE  | Optimize Top-1 判定 |
| --------- | ------------- | ------ | ----- | ------------------- |
| Sample1   | `>0`          | 1.0000 | 0.034 | ✓ Match             |
| Sample2   | `>0`          | 1.0000 | 0.024 | ✓ Match             |
| Sample3   | `>`           | 0.9963 | 0.543 | ✓ Match             |
| Sample4   | `=5`          | 0.9968 | 0.134 | ~ Partial           |
| Sample5   | `<10`         | 0.9983 | 0.136 | ✓ Match             |
| Sample6   | `>0`          | 0.9998 | 0.170 | ~ Partial           |
| Sample7   | Y1:`>0`, Y2:`>0` | Y1:1.0000 / Y2:0.9999 | 0.039/0.050 | ✓ Match |
| Sample8   | `>0`          | 0.9997 | 0.024 | ~ Partial（改善）   |
| Sample9   | `>`           | 0.9999 | 0.245 | ✓ Match             |
| Sample10  | `>0`          | 1.0000 | 0.019 | ✓ Match（改善）     |

注目点は、R²が最も低い Sample3（0.9963）でも Optimize は正解を指し示せていることです。R² ≈ 1 であっても部分一致になるケース（Sample6, 8）があるのは、**フィットが良くても線形係数の符号が誤方向に引っ張られると推薦が外れる**ことを意味しています。「R²が高い = 推薦が正確」という単純な対応にはなりません。

## 7. まとめとベストプラクティス

今回の10サンプル検証から得られた知見をまとめます。

**第一に、セミパラメトリックBayesは線形 + 非線形の複合問題に強いですが、強い交互作用項があるとき線形成分に「リーク」が起きやすいという弱点があります。** Sample6・8・3はいずれも `X1*X2` 交互作用を含んでおり、その積をDataシートに導出変数として追加しても、線形β が交互作用の主効果を吸収してしまいました。交互作用が支配的な問題では、**より多くのデータ点（特に高次元コーナー近傍）** を集めてGPに残差を学ばせることが有効です。

**第二に、OptimizeモードとExploreモードは意図的に使い分けることが重要です。** 特にモデルの不確実性が大きい序盤では Explore を優先し、SDが縮小してきた後に Optimize に切り替えると、Sample8・10 のようなデータ品質由来のミスを早期に検知・修正できます。

**第三に、変数を固定した実験データはその変数をモデルに「見えなく」します。** Sample8・10の改善事例が示すとおり、実験計画において **すべての変数を十分に変化させる** ことが正確な推薦の前提条件です。AutoXP3のDefinitionに変数を定義したからといって、Dataシートに固定値しかなければその変数の効果はGPにも線形成分にも学ばれません。

**第四に、Purpose の記述精度は最適化方針そのものに直結します。** Sample4では `=5` というターゲット最適化が内部で `None` として処理されており、推薦が目標値から乖離しました。Purpose 記法の仕様を正確に理解して定義することが、期待通りの推薦を得るうえで欠かせません。

## 8. まとめ

AutoXP3のセミパラメトリックBayesモデルは、10サンプル中7件で最適条件を正確に発見し、残り3件も正解方向の一部を正しく捉えていました（不一致は0件）。R²は全サンプルで 0.996 以上を達成しており、サロゲートモデルとしての回帰性能は非常に安定しています。

一方で「R²が高ければ推薦も正確」という単純な対応は成立しないことも明らかになりました。**交互作用が強い問題では線形係数が誤方向に引っ張られ、データが偏っている問題では変数の効果が正しく学ばれない**、という2種類の落とし穴が存在します。

AutoXP3を効果的に使うための実践的な指針は、「**Explorerで空間を探索しながら、全変数を均等に変化させた実験データを積み上げ、SDが十分に小さくなってからOptimizeで収束させる**」という一言に集約されます。アルゴリズムの精度を最大限に引き出すのは、Definitionシートの設計と、それに沿った実験計画の質です。
